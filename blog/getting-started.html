Getting Started with AI Experimentation

Transform your ML development from ad-hoc scripting to systematic experimentation. Set up tracking, design experiments, and make decisions based on evidence rather than intuition.

Why Systematic Experimentation Matters

Most ML practitioners start by writing training scripts, checking results, and making changes based on gut feeling. This works for simple projects, but it breaks down as soon as you need to answer questions like "which of the 12 configurations I tried last week performed best?" or "can we reproduce the results from three months ago?" or "does this new feature actually improve the model, or was the improvement from the learning rate change I made at the same time?"

Systematic experimentation means treating ML development as a scientific process: formulate a hypothesis, design a controlled experiment to test it, record all variables, and analyze results statistically. This discipline eliminates the confusion, wasted compute, and false confidence that plague undisciplined ML development.

Setting Up Experiment Tracking in 5 Minutes

The fastest way to start tracking experiments is with Weights and Biases. Create a free account, install the library, and add four lines to your training script: 

import wandb

# Initialize a new run
wandb.init(
    project="my-first-experiment",
    config={
        "learning_rate": 0.001,
        "epochs": 10,
        "batch_size": 32,
        "model": "resnet18",
        "optimizer": "adam",
    }
)

# Inside your training loop
for epoch in range(config.epochs):
    train_loss = train_one_epoch(model, train_loader)
    val_loss, val_acc = evaluate(model, val_loader)

    # Log metrics — that's it
    wandb.log({
        "train_loss": train_loss,
        "val_loss": val_loss,
        "val_accuracy": val_acc,
        "epoch": epoch,
    })

wandb.finish()

With just wandb.init() and wandb.log(), every training run is automatically recorded with its hyperparameters, metrics over time, system utilization, and even the git commit hash. Designing Your First Controlled Experiment

A controlled experiment changes exactly one variable while keeping everything else constant. This is the only way to establish causation rather than correlation. If you want to know whether dropout helps your model, run the same training setup twice: once with dropout and once without. Same data, same learning rate, same number of epochs, same random seed. The difference in performance can then be attributed to dropout alone.

In practice, exact reproducibility requires controlling several sources of randomness: the random seed for weight initialization, the data shuffling order, and any stochastic operations in your model or data augmentation pipeline. Set these explicitly at the start of every experiment: 

import random
import numpy as np
import torch

def set_seed(seed=42):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False

Note that perfect determinism on GPU is not always achievable due to non-deterministic CUDA operations, but setting these seeds ensures that differences between runs are due to your changes rather than random variation.

Running Your First Hyperparameter Sweep

Once you have experiment tracking in place, running a hyperparameter sweep is straightforward. Optuna provides the most flexible framework. Define an objective function that trains your model with a trial's suggested hyperparameters and returns the validation metric: 

import optuna

def objective(trial):
    lr = trial.suggest_float("lr", 1e-5, 1e-2, log=True)
    dropout = trial.suggest_float("dropout", 0.0, 0.5)
    hidden_size = trial.suggest_int("hidden_size", 64, 512, step=64)

    model = build_model(hidden_size, dropout)
    val_acc = train_and_evaluate(model, lr)
    return val_acc

study = optuna.create_study(direction="maximize")
study.optimize(objective, n_trials=50)

print(f"Best trial: {study.best_trial.params}")
print(f"Best accuracy: {study.best_value}")

Analyzing Results Meaningfully

A single number (accuracy, loss) is never sufficient to evaluate a model. Always look at the full picture: training and validation curves over time (to detect overfitting), performance broken down by data subgroups (to detect bias), confusion matrices for classification (to understand error patterns), and confidence intervals rather than point estimates. Run each experiment multiple times with different random seeds to understand the variance of your results — a model that achieves 92% accuracy on one seed but 86% on another is less reliable than one that consistently achieves 89%.

When comparing two models, use statistical tests appropriate for your situation. For paired comparisons (same test set), a paired t-test or Wilcoxon signed-rank test tells you whether the difference is statistically significant. Next Steps

Start tracking experiments today — even informal tracking is infinitely better than no tracking. As your practice matures, add automated sweeps, formal ablation studies, and statistical significance testing. The investment in experimental rigor pays for itself many times over through faster iteration, fewer dead ends, and confidence that your shipped models are genuinely better than their predecessors.
